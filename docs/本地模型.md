# 本地模型

Jot 默认把润色交给本机的 Ollama：

```text
llm_base_url = http://127.0.0.1:11434/v1
llm_model    = qwen3:1.7b
```

这不是必须的。你可以把这两个值换成任意 OpenAI 兼容的云端服务，也可以直接关掉润色。

## 为什么默认用本机模型

- **润色这一段不离开本机**：请求发往 `127.0.0.1`，不经过外部服务。转写是否离开本机，取决于你在「识别」页配置的转写服务。
- **不需要 API Key**：本地 Ollama 通常不校验密钥，设置里留空即可。
- **没有按次计费**：只消耗本机的 CPU / GPU。
- **润色可以离线**：模型拉取完成后，断网也能润色；转写仍然需要可用的转写服务。

代价是：

- 首次请求要把模型加载进显存，明显更慢；
- 本机算力有限，模型越大越慢；
- 小模型对生僻术语、复杂句式的处理不如云端大模型。

默认选 `qwen3:1.7b` 而不是更大的模型，是因为润色只做短文本整理：补标点、去口头语、保持原意。1B–2B 级别已经够用，热态单次在百毫秒级；8B 对复杂句式和生僻术语更稳，但大多数短句的提升有限，体积和耗时却更高。

如果本机没有安装 Ollama，默认配置会在每次听写时先尝试润色，失败后回退原文。没有本地模型时，建议先到「润色」页关掉开关，或者直接改成云端接口。

## 安装 Ollama

### Windows

1. 从 Ollama 官网下载 Windows 安装包并安装。
2. 安装完成后打开新的 PowerShell，确认命令可用：

```powershell
ollama --version
```

Ollama 通常会在后台运行，监听 `127.0.0.1:11434`。

### macOS

用安装包安装，或：

```bash
brew install ollama
```

安装后启动 Ollama 应用，或运行：

```bash
ollama serve
```

### Linux

按 Ollama 官网的安装说明安装。安装完成后确认服务在运行：

```bash
ollama --version
curl http://127.0.0.1:11434/v1/models
```

如果 `curl` 连接被拒绝，先启动服务：

```bash
ollama serve
```

### 拉取模型

```bash
ollama pull qwen3:1.7b
ollama list
```

先单独跑一次，确认模型能正常生成：

```bash
ollama run qwen3:1.7b "把这句话整理通顺：嗯，我们今天呢，主要聊一下接口联调"
```

第一次运行会加载模型，耗时明显更长。默认不需要更大的模型；确实需要更高质量时再拉取 8B：

```bash
ollama pull qwen3:8b
```

## 模型怎么选

润色是「短文本整理」任务，不是知识问答。输入通常是几十到几百个字，输出也是同量级；补标点、去口头语、保持原意，1B–2B 级别就够，不需要大模型。

| 参数量 | 4-bit 模型体积（约） | 实际显存 / 统一内存（约） | 建议 |
|---|---|---|---|
| 1.7B | 1.4 GB | 2–3 GB | 默认；速度和够用的平衡点 |
| 4B | 2.5 GB | 3–4 GB | 可选；避开早期构建，见下文 |
| 8B | 5.2 GB | 6–8 GB | 显存充足、质量优先时使用 |
| 14B | 9–10 GB | 12–16 GB | 短文本润色收益有限 |
| 32B | 20 GB 左右 | 24 GB 以上 | 不建议只为润色使用 |

实际显存还要加上下文 KV cache、运行时开销和桌面环境占用。表里的数字是粗略范围，不是硬门槛。macOS 的统一内存由系统和 GPU 共享，同样只能作为起点。

选型建议：

- **默认用 `qwen3:1.7b`**。中文标点、口头语清理已经够用，热态单次约 148 ms。
- **显存够，想换质量**：用 `qwen3:8b`。热态单次约 434 ms，体积 5.2 GB，比 1.7B 慢一些，但复杂句式和生僻术语更稳。
- **追求响应速度**：留在 1.7B，不要为了「参数量更大」上 8B。
- **避开 Qwen3-4B 的早期构建**。这类旧构建的对话模板里写死了思考分支，`reasoning_effort=none` 关不掉，单次会到 13–21 秒，输出里还会出现 `</think>` 和一大段推理。程序会丢弃 `</think>` 之前的内容，但延迟仍然高，不要选这类模型。
- **14B / 32B**：短句润色的收益通常抵不上体积和延迟，除非你经常整理长段落、复杂结构。

## 延迟实测

以下数据来自 RTX 5060 Ti、热态、同一段中文听写文本、6 次取中位。其中 1.7B 和 8B 关闭了模型思考；4B 旧构建的思考分支关不掉，仅作对照：

| 模型 | 单次耗时 | 模型体积 | 备注 |
|---|---|---|---|
| `qwen3:1.7b` | 148 ms | 1.4 GB | 关闭思考，默认 |
| `qwen3:8b` | 434 ms | 5.2 GB | 关闭思考，质量优先 |
| `qwen3:4b`（旧构建） | 13–21 秒 | 2.5 GB | 思考关不掉，不要选 |

这是特定硬件上的结果，不是所有机器的保证。其他场景的量级：

| 场景 | 大致量级 |
|---|---|
| 首次请求，或模型被卸载后重新加载 | 额外数秒到数十秒 |
| 纯 CPU 推理 | 明显更慢，常见十几秒 |
| 14B / 32B | 没有实测；通常明显高于 8B |

### 关闭思考为什么有效

qwen3 这类推理模型默认会先输出几百字的内部推理，再给最终答案。对「把这句话整理通顺」这种任务，这段推理没有太大价值，却占掉了大部分时间：关闭思考时单次在 0.15 秒级，开启后会变成 8 秒以上。

`llm_disable_thinking = true` 时，Jot 会在请求里发送：

```json
{ "reasoning_effort": "none" }
```

模型直接输出结果，不再先「想」一遍。

如果服务不认识这个参数并返回 4xx，应用会去掉该字段重试一次，避免整次润色失败。极少数旧模型构建仍然会把思考内容当正文输出；应用会丢弃 `</think>` 之前的内容，只保留后面的结果。如果输出仍然混有思考段，升级 Ollama 或换一个模型。

### 测试连接的耗时代表什么

设置页「测试连接」发送的是一条内容为 `ping` 的非流式请求，显示的是这一来一回的耗时，包含建连和少量生成。它不等于正式润色的首字延迟，也不包含长文本的生成时间。正式润色是流式的，首字通常比整段完成更快。

## 在 Jot 里配置

到「润色」页填写：

| 配置项 | 建议值 |
|---|---|
| `polish_enabled` | 开启 |
| `llm_base_url` | `http://127.0.0.1:11434/v1` |
| `llm_model` | `qwen3:1.7b` |
| API Key | 留空 |
| `llm_disable_thinking` | 开启 |
| `polish_style` | `clean`（默认） |

保存后点「测试连接」。成功只说明地址、模型和鉴权可用；正式润色还要求服务支持 SSE 流式响应。

如果 Ollama 跑在局域网另一台机器上，把 `127.0.0.1` 换成那台机器的地址，并让 Ollama 监听非回环地址。注意这会把转写文本发送到局域网内的另一台机器。

## 常见问题

**连接被拒绝（connection refused）**

Ollama 没在运行，或者端口不是 11434。先执行：

```bash
ollama serve
```

再确认：

```bash
curl http://127.0.0.1:11434/v1/models
```

**返回 404**

最常见的原因是 `llm_base_url` 少了 `/v1`。Jot 只会补 `/chat/completions`，不会自动补 `/v1`。正确写法是：

```text
http://127.0.0.1:11434/v1
```

另一个原因是模型没有拉取。执行 `ollama list` 确认 `qwen3:1.7b` 存在。

**报模型不存在（model not found）**

```bash
ollama pull qwen3:1.7b
```

然后重新测试。模型标签会更新，以 `ollama list` 或模型库里的实际标签为准。

**第一次润色特别慢**

模型正在加载。先用 `ollama run qwen3:1.7b` 预热一次，或者接受第一次请求的额外延迟。`ollama ps` 可以看当前有哪些模型在内存里。

**显存不够 / 系统卡顿**

换更小的模型（`qwen3:1.7b`），关闭占用 GPU 的其他程序，或者改用云端接口。8B 需要更多显存；14B / 32B 对短文本润色的收益通常抵不上资源开销。

**输出里还有思考过程**

确认 `llm_disable_thinking` 是开启的。然后升级 Ollama，或换一个不强制输出思考段的模型。Qwen3-4B 的早期构建属于关不掉思考的类型，表现是输出里出现 `</think>` 和一大段推理，建议直接换模型。应用会尝试丢弃 `</think>` 之前的内容，但不能保证所有模型格式都一致。

**润色结果不如原文**

先关掉润色，确认原始转写是否已经够用。也可以把风格改成 `minimal`，减少模型改写。词典里的 `术语 = 说明` 能帮助模型选对同音字，但它是提示，不是强制替换。
