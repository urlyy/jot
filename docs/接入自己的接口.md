# 接入自己的接口

Jot 不绑定服务商。转写和润色是两条独立的链路，可以分别指向不同的服务：

| 用途 | 配置字段 | 实际请求 |
|---|---|---|
| 转写 | `stt_base_url`、`stt_model`、`stt_language` | `multipart/form-data` POST 到 `/audio/transcriptions` |
| 润色 | `llm_base_url`、`llm_model` | JSON POST 到 `/chat/completions`，按 SSE 流式读取 |

火山引擎是转写的第二种接入方式，不走上面的 HTTP 端点；见第 5 节。

## 1. 地址怎么拼

程序只做三件事：

1. 去掉地址首尾空格；
2. 要求地址以 `http://` 或 `https://` 开头，且不包含空格或其他空白字符；
3. 去掉末尾的 `/`，然后检查是否已经以目标路径结尾。已经结尾就直接使用，否则追加目标路径。

它**不会自动补 `/v1`**。你的服务需要 `/v1`，就把 `/v1` 写进地址里。

### 转写地址

| 填到 `stt_base_url` | 实际请求 |
|---|---|
| `https://api.openai.com/v1` | `https://api.openai.com/v1/audio/transcriptions` |
| `https://api.openai.com/v1/` | `https://api.openai.com/v1/audio/transcriptions` |
| `https://api.openai.com/v1/audio/transcriptions` | 原样使用 |
| `https://api.openai.com/v1/audio/transcriptions/` | 去掉末尾 `/` 后原样使用 |
| `http://localhost:8000` | `http://localhost:8000/audio/transcriptions` |

最后一行不是错误，但多数服务需要 `/v1`，所以更常见的写法是 `http://localhost:8000/v1`。

### 润色地址

| 填到 `llm_base_url` | 实际请求 |
|---|---|
| `https://api.deepseek.com/v1` | `https://api.deepseek.com/v1/chat/completions` |
| `https://api.deepseek.com/v1/` | `https://api.deepseek.com/v1/chat/completions` |
| `https://api.deepseek.com/v1/chat/completions` | 原样使用 |
| `https://api.deepseek.com/v1/chat/completions/` | 去掉末尾 `/` 后原样使用 |
| `https://api.deepseek.com` | `https://api.deepseek.com/chat/completions` |

地址为空时，转写通常显示 `stt_not_configured`，润色显示 `llm_not_configured`。地址格式不对（不是 `http://` / `https://` 开头，或包含空白字符）时，转写通常显示 `stt_not_configured`；润色会回退原文并显示 `llm_failed`。

## 2. 转写接口

### 请求

```http
POST <转写端点>
Authorization: Bearer <API Key>        # Key 非空时才发送
Content-Type: multipart/form-data
```

表单字段：

| 字段 | 是否总是发送 | 说明 |
|---|---|---|
| `file` | 是 | 文件名 `audio.wav`，MIME `audio/wav` |
| `model` | 是 | `stt_model` 的值 |
| `language` | 否 | `stt_language` 不是 `auto` 或空时才发送 |
| `prompt` | 否 | 词典非空时发送；流式分段时还会附加上文 |

音频格式固定为 **16 kHz、单声道、16-bit PCM**，文件是标准 WAV。整段音频最多约 24 MB，对应约 12.5 分钟；单次录音上限默认 30 秒，最大可设 600 秒。

`prompt` 的组成：

- 词典里的**术语本身**，用 `、` 连接，截断到 200 个字符；
- 流式分段请求时，再拼上已确认文本的末尾 200 个字符，帮助模型保持术语和上下文一致。

`术语 = 说明` 里的说明不会发送给转写接口，只用于润色。

### 响应

成功时返回 JSON，程序读取 `text` 字段：

```json
{ "text": "识别出来的文字" }
```

`text` 为空或缺失时，按「没有检测到语音」处理，显示 `no_speech`。

### 超时与重试

- 单次 HTTP 请求超时 60 秒；
- 遇到 5xx 或超时会重试，总共最多 3 次尝试（2 次重试），间隔 1 秒、2 秒；
- 4xx 不重试，直接按鉴权或请求错误处理；
- 整段转写还有一个更外层的等待上限，避免界面一直停在「转写中」。

### 流式听写怎么发请求

OpenAI 兼容路径的「流式」是**分段批式**，不是 WebSocket 音频流：

1. 录音期间每隔 `streaming_interval_ms`（默认 1200 毫秒）取一段新增音频；
2. 新增音频不足 400 毫秒时跳过这一轮；
3. 每一段都按上面的格式单独请求一次，并带上 `prompt` 上下文；
4. 分段请求失败只记日志，不中断录音；
5. 松手后：
   - `streaming_insert = false`（默认）：丢弃分段结果，对整段音频再请求一次，作为最终稿；
   - `streaming_insert = true`：分段结果已经键入光标处，只补转写最后一段，不再整体重转，并跳过润色。

如果服务按请求次数计费，调大 `streaming_interval_ms` 可以减少请求数；关闭 `streaming_enabled` 则完全不发分段请求。

## 3. 对话接口

### 请求

```http
POST <对话端点>
Authorization: Bearer <API Key>        # Key 非空时才发送
Content-Type: application/json
```

请求体：

```json
{
  "model": "qwen3:1.7b",
  "messages": [
    { "role": "system", "content": "……风格、词典、自定义要求……" },
    { "role": "user", "content": "以下是语音听写的原始文字，请按规则润色后只输出正文：\n\n……" }
  ],
  "stream": true,
  "temperature": 0.3,
  "reasoning_effort": "none"
}
```

- `reasoning_effort` 只在 `llm_disable_thinking = true` 时发送。服务返回 4xx 时，应用会去掉这个字段重试一次。
- 请求体不发送 `max_tokens`，由服务端默认值决定输出上限。
- system prompt 会包含润色风格、词典术语及说明（最多 100 条）、自定义要求（最多 2000 字符）。
- 服务必须支持 `stream: true` 的 SSE 响应。只支持非流式响应的服务会在正式润色时失败。

### 响应

按 SSE 解析，每行以 `data:` 开头：

```text
data: {"choices":[{"delta":{"content":"你好"}}]}

data: [DONE]
```

程序取 `choices[0].delta.content` 作为增量文本。以下情况会失败并回退原文：

- HTTP 状态不是 2xx；
- SSE 行不是合法 JSON；
- 响应里的 `error.message` 非空；
- 流结束后没有拿到任何文本。

单次润色请求超时 60 秒。超时、网络错误、HTTP 错误、空输出都会显示 `llm_failed`，但**已经转写出来的文字不会丢**，会直接输出原文。

### 「测试连接」测的是什么

设置页的测试连接会发一次真实请求，但它和正式润色不完全一样：

- 转写测试：发送 0.1 秒静音 WAV，验证地址、模型和鉴权；火山引擎路径会建立 WebSocket，发送 0.2 秒静音并等待短暂时间，主要验证连通和鉴权。
- 润色测试：发送一条内容为 `ping` 的非流式请求（`stream: false`），返回耗时。

所以润色测试成功，只说明地址、模型和鉴权可用；如果服务不支持 SSE 流式，正式润色仍可能失败。测试显示的毫秒数也不等于正式润色的首字延迟。

## 4. 鉴权

OpenAI 兼容接口统一使用 Bearer：

```http
Authorization: Bearer <API Key>
```

- Key 为空时不发送 `Authorization` 头，方便本地无鉴权服务；
- Key 保存在系统钥匙串，不写入 `settings.json`；
- 转写 Key 和润色 Key 分开保存，可以属于不同服务商；
- 设置页里输入后失焦即保存，清空后失焦即删除。

火山引擎使用另一套请求头：

- UUID 形式的 Key → `X-Api-Key`
- `app_key:access_key` → `X-Api-App-Key` + `X-Api-Access-Key`
- 另带 `X-Api-Resource-Id` 和 `X-Api-Connect-Id`

## 5. 火山引擎（可选）

把 `stt_provider` 设为 `volcengine` 后，转写走原生 WebSocket 流式识别，不经过 `stt_base_url` / `stt_model`。

- 内置端点：`wss://openspeech.bytedance.com/api/v3/sauc/bigmodel_async`
- `stt_volc_resource_id`：
  - `volc.seedasr.sauc.duration`（默认，SeedASR 流式）
  - `volc.bigasr.sauc.duration`（BigASR 流式）
- 音频：16 kHz、单声道、16-bit PCM，按约 30 毫秒的节奏发送分片
- 语言：`auto` 不发送；`zh` → `zh-CN`，`en` → `en-US`，`ja` → `ja-JP`，`ko` → `ko-KR`；其他代码原样发送
- Key：不能为空；填语音识别控制台的 UUID，或旧版 `app_key:access_key`；方舟的大模型 Key 不能用于语音识别
- 存储：火山引擎 Key 与 OpenAI 兼容 Key 分别存放在钥匙串的 `stt` / `volcengine` 和 `stt` / `custom` 条目

火山引擎协议没有词典字段，因此词典不会影响这条路径的转写；词典说明仍会在润色时使用。

## 7. 错误码

胶囊里的文案由错误码映射而来，完整映射如下：

| 错误码 | 胶囊文案 | 常见原因 | 处理 |
|---|---|---|---|
| `mic_unavailable` | 麦克风不可用，请检查系统权限 | 没有输入设备、系统录音权限未给、设备被占用、启动超时 | 检查系统输入设备和权限；关掉占用麦克风的应用 |
| `stt_not_configured` | 还没有配置转写接口 | 转写地址或模型为空、地址格式不对、火山引擎 Resource ID 或 Key 为空 | 到「识别」页补齐并测试连接 |
| `stt_auth` | 转写接口鉴权失败，请检查 API Key | 401/403、Key 填错、用了另一家服务的 Key、火山引擎鉴权失败 | 确认 Key 属于当前服务；火山引擎不要填方舟 Key |
| `stt_failed` | 转写失败，请稍后重试 | 5xx、网络错误、超时、响应不是合法 JSON、其他 HTTP 错误 | 看「测试连接」的详细报错；检查网络和服务状态 |
| `no_speech` | 没有检测到语音 | 录音为空、麦克风静音、说话太短、接口返回空文本 | 检查输入设备；靠近麦克风、说完整一句 |
| `llm_not_configured` | 还没有配置润色接口 | 开启了润色，但对话地址或模型为空 | 补全配置，或直接关闭润色 |
| `llm_failed` | 润色失败，请稍后重试 | HTTP 错误、超时、SSE 解析失败、服务不支持流式、返回空文本 | 文字会回退原文；检查服务和模型 |
| `output_failed` | 文字输出失败 | 直接键入和剪贴板写入都失败 | 检查权限；改用剪贴板模式手动粘贴 |
| `accessibility_required` | 需要辅助功能权限才能输入文字 | macOS 未授权辅助功能 | 到系统设置授权；文字会先复制到剪贴板 |
| `internal` | 出现内部错误 | 配置读取失败、启动/停止录音异常 | 重启应用；仍复现再看日志 |

未识别的错误码会显示为 `操作失败（<code>）`。

`pipeline:error` 还带有可选的 `details` 字段，但胶囊只显示上表中的固定文案；设置页「测试连接」会显示更具体的中文错误，例如 `转写接口返回 401：...`。

## 8. 用 curl 验证

替换地址、Key 和音频路径后，可以先绕过应用直接验证服务。

转写：

```bash
curl -X POST "https://api.openai.com/v1/audio/transcriptions" \
  -H "Authorization: Bearer $STT_KEY" \
  -F "file=@sample.wav" \
  -F "model=whisper-1"
```

润色（流式）：

```bash
curl -N -X POST "http://127.0.0.1:11434/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3:1.7b",
    "messages": [{ "role": "user", "content": "你好" }],
    "stream": true
  }'
```

Windows PowerShell 里用 `curl.exe`，环境变量写成 `$env:STT_KEY`，续行用反引号。

如果 curl 正常而应用不正常，优先检查两件事：地址是否多了或少了 `/v1`，以及服务是否支持应用实际发送的字段（`prompt`、`reasoning_effort`、SSE 流式）。
